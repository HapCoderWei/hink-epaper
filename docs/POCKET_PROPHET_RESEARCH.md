# 口袋先知 Rand/0 调研与 HINK 对照基线

更新日期：2026-09-13

本文记录「口袋先知」公开资料和第三方实测结果，作为后续与 HINK 2.13 黑白红电子价签改造项目逐项对比的基线。宣传资料、社区实测和推断分开标注；没有可靠来源的参数不写成既定事实。

## 1. 产品定位

「口袋先知」正式产品名为 Rand/0，由思维重置（MindReset）团队与少数派共创。它不是通用信息终端，而是一款可放进口袋或挂在包上的“轻回应装置”：用墨水屏、实体按键和摇动动作，为日常犹豫、无聊或情绪停顿提供一次简短回应。

公开资料将其描述为接近 AirPods 2 耳机盒大小的微型电子纸设备。首发时间为 2026 年 4 月 23 日，首发宣传价格约 99 元；后续不同渠道和活动价格可能变化，不将 99 元视为长期定价。

## 2. 已公开的主要能力

- 1.54 英寸非发光电子墨水屏。
- 两个实体按键，支持短按和长按。
- 支持“摇一摇”等动作交互，说明设备包含运动感应能力。
- 答案之书，公开资料称内置约 350 条中英文答案。
- MBTI 人格指南：根据人格类型调整提示语气。
- 每日运势、幸运色和宜忌。
- 抛硬币、掷骰子、随机数字、电子木鱼等轻量玩法。
- 日历和时间，使用 Wi-Fi 自动校时。
- 蓝牙翻页遥控。
- NFC 卡片相关功能。
- 自定义锁屏：上传照片并转换为四级灰度画面。
- Wi-Fi、蓝牙和 OTA 升级能力。

这些能力的共同点不是信息量大，而是单次交互短、结果明确、无需进入手机信息流。产品价值主要来自“内容、动作和仪式感”的组合，而不只是拥有一块墨水屏。

## 3. 屏幕与图像格式

第三方项目通过厂商图片转换接口返回的预览图进行了实测，确认：

- 原生画布为 **200 × 200**。
- 显示为 **4 级灰度**。
- 预览图中实际灰度值为 `{0, 85, 170, 255}`。
- 官方转换接口提供多种抖动核，包括 Threshold、Floyd–Steinberg、Atkinson、Sierra、Burkes、Stucki 和 Jarvis–Judice–Ninke 等。
- 扁平图标、粗体文字和高对比布局最适合该屏幕；照片和大面积渐变会增加抖动噪点和编码负载。

以上 200 × 200 和灰度值属于第三方对官方接口输出的实测结果，不是本文独立拆机确认。

## 4. 无线与壁纸更新机制

### 4.1 Wi-Fi 壁纸通道

第三方实测发现，设备进入“更换壁纸”界面后才接入局域网，并在 80 端口开放极简 HTTP 服务。已识别的壁纸接口包括：

- `GET /wallpaper/info`：读取壁纸容量和上传限制。
- `POST /wallpaper`：写入厂商私有编码的壁纸数据。
- `DELETE /wallpaper`：恢复出厂内建壁纸。

实际流程为：

1. 用户在设备上进入“更换壁纸”。
2. 设备临时连接 Wi-Fi。
3. 原始图片上传到厂商云端转换接口。
4. 云端返回预览图和 `COMPRESS_ARRAY_V2` 私有编码。
5. 浏览器把私有编码 POST 到设备。
6. 保存完成或退出界面后，设备离开该网络工作状态。

该通道存在几个重要约束：

- 图片转换依赖厂商云端，是链路中的外部依赖。
- HTTP 通道可以写入壁纸，但不能读回当前显示内容、电池状态、按键事件等信息。
- 设备平时不保持 Wi-Fi 在线，因此不能在原厂交互逻辑下随时被后台服务器推送。
- 设备没有上一张用户壁纸的读回接口，外部工具需要自行保存历史源图。

### 4.2 蓝牙通道

公开资料确认设备支持蓝牙翻页。第三方在 macOS 上进一步实测到设备以 `Rand/0 Pager` 名称出现，并以 BLE HID 键盘身份提供按键和多媒体控制能力。

社区根据设备的 Wi-Fi/BLE 地址关系和 NimBLE 标识，判断内部主控属于 ESP32 系列。这一结论有较强实测依据，但仍属于**非官方硬件身份推断**，在没有拆机丝印或官方规格前不写成绝对结论。

第三方实测还表明，蓝牙翻页和 Wi-Fi 壁纸功能受到设备菜单模式控制：进入相应界面时开启，退出后关闭。原厂固件下两条通道不适合作为常驻双向通信链路。

| 主控 | 社区推断为 ESP32 系列 | 已确认 TLSR8359F512ET32 |
| 内容更新 | Wi-Fi 页面、厂商云端转换、设备局域网接口 | Web Bluetooth 直接传图，无业务后端 |

| OTA | 原厂宣传支持，公开资料未说明底层恢复机制 | OTA v2 M2 已完成双槽、断电继续和失败回滚真机验证；正常升级不需要连接烧录器 |

### 5.1 局部刷新专项对比（2026-09-12）

#### Rand/0：已确认存在快速刷新路径，但“局部窗口”尚未被直接证明

演示视频中，图形和文字可以在没有多轮黑白闪烁的情况下快速切换。这个观察与官方文档一致：MindReset 的 Rand/0 使用说明明确写明，为改善显示质量和减少残影，屏幕会**偶尔执行一次全刷新**。这意味着正常交互并非每次都走慢速全刷，而是存在一种更快、允许积累少量残影的刷新路径。

目前公开资料仍不足以区分以下两种底层实现：

1. 真正的区域局刷：只向控制器写入并刷新发生变化的矩形区域。
2. 整屏差分快刷：整屏寻址，但驱动波形只处理新旧画面发生变化的像素。

两者在演示视频里都会表现为“图形直接变成另一个图形、没有整屏反复闪烁”。因此可以确认的是 **Rand/0 支持用户可感知的快速增量刷新**，但在没有面板型号、控制器资料或固件驱动源码前，不把它进一步写成“已确认采用局部窗口刷新”。官方“偶尔全刷”的策略也说明快刷会产生残影，需要周期性全刷清理。

#### HINK：丝印反查与命令指纹（2026-09-12 补充）

实物 FPC 完整丝印为 `HINK-E0213A162-FPC-A0`，另有标记 `DEM 2145`。公开网络中没有找到 `A162` 的原厂规格书，但已经得到以下可重复核对的证据：

| 证据 | 能确定什么 | 不能据此确定什么 |
|---|---|---|
| 江西兴泰的贸易记录出现 `FPC E0213A162/A1` | `E0213A162` 是江西兴泰 HINK/SEEKINK 体系的 FPC 设计编号 | 不能单独确定光学膜、控制器批次或 LUT |
| HINK/SEEKINK 官网确认江西兴泰是 EPD 模组设计制造商 | 丝印中的 HINK 厂牌归属明确 | 官网没有公开这块 A162 的数据手册 |
| Arduino 社区有完全相同 `HINK-E0213A162-FPC` 实物记录 | 该 FPC 曾用于其他 2.13 英寸产品；删除 `0x61` 后可用微雪 `epd2in13bc` 序列驱动 | 社区记录不是原厂规格，且相同 FPC 丝印出现过不同批次行为 |
| 本项目已验证的命令序列与微雪官方 `epd2in13bc` 驱动逐项吻合 | 控制器属于 `0x10/0x13` 双平面、`0x12` 刷新的旧款三色命令家族 | 不能仅凭兼容命令断言控制器的精确型号 |

当前 HINK 实物是 122 × 250 黑/白/红三色面板。已验证驱动发送完整的 4000 字节黑色平面和 4000 字节红色平面，再执行 `0x12 DISPLAY_REFRESH`；`EPD_Display()` 目前明确忽略 `full_or_partial` 参数。实物刷新约 18 秒，并伴随三色粒子迁移所需的多阶段闪烁。这个表现与同代三色面板公开的 12～15 秒级全刷接近。

这里需要区分两个容易混淆的概念：

1. **局部窗口**：控制器只扫描一个矩形区域。
2. **快速刷新**：使用明显更短的驱动波形，使画面无多轮闪烁地快速变化。

与当前命令指纹相同的旧款微雪控制器资料确实定义了 `0x90 PARTIAL WINDOW`、`0x91 PARTIAL IN`、`0x92 PARTIAL OUT`，所以不能再说控制器“没有区域命令”。这还提示当前源码把 `0x92` 注释成 `DATA_STOP` 只是沿用了示例写法；在这份最接近的控制器命令表中，它实际表示退出局部模式。由于精确控制器仍未确认，后续只能把这点作为反向识别证据，不能直接据此改生产驱动。

但是，局部窗口寄存器存在并不等于这块三色膜具备可用的快速波形。公开的对应三色参考程序只给出完整黑/红双平面刷新；同尺寸黑白红面板通常标称约 13～15 秒全刷，而同尺寸黑白二色屏才明确提供约 0.3 秒局刷。Good Display 也提醒，部分新型号三色屏已经能做特定颜色的局刷，因此“三色屏永远不能局刷”同样过于绝对，仍然必须以精确面板和 LUT 为准。

对我们这块实物，分级结论是：

- **黑/白/红完整彩色快刷：没有资料或实测支持，按不支持处理。**
- **使用原厂全刷波形的矩形窗口刷新：控制器家族可能支持，但预计仍慢，而且尚未在 A162 实物验证。**
- **黑白平面自定义短 LUT 快刷：理论上不能完全排除，属于逆向实验，不是已确认能力。** 红色平面必须保持不变，并需验证红色串扰、残影、BUSY 时序和全刷恢复。
- **当前可靠能力：约 18 秒的完整三色刷新。**

强行套用其他控制器或黑白屏的快速 LUT，可能造成红色串扰、严重残影、对比度下降或刷新失败。即使实验成功，也需要周期性三色全刷清残影，不能先承诺达到 Rand/0 的直接切换效果。

#### 当前工程结论

| 能力 | 口袋先知 Rand/0 | HINK 当前方案 |
|---|---|---|
| 无多轮整屏闪烁的快速切换 | 已由官方说明和演示现象支持 | 当前驱动不支持，硬件没有已验证快刷波形 |
| 真正矩形窗口局刷 | 尚未直接证明 | 命令家族存在窗口寄存器，但 A162 实物未验证 |
| 周期性全刷清残影 | 官方明确会偶尔发生 | 每次都是三色全刷 |
| 红色参与快速局刷 | 不适用，Rand/0 为四灰阶 | 没有证据支持 |
| 当前典型体验 | 快速交互，偶尔全刷 | 约 18 秒完整三色刷新 |

产品开发时仍应按 **HINK 不支持可靠快刷** 设计。若目标是复制 Rand/0 的按键即时反馈体验，最可靠的路线是更换为明确支持局刷的黑白二色面板；保留现有 HINK 三色屏时，则应把红色和慢速全刷用于低频内容，例如壁纸、状态卡、每日一句和价格牌。

后续如要探索 HINK 的极限，可另做一块可恢复的测试机，只尝试“黑白平面快刷、红色平面保持不变”的实验驱动，并在多轮循环中检查残影、红色污染、BUSY 时序和全刷恢复能力。在面板控制器与原厂 LUT 未确认前，不应把该实验固件烧入唯一或已经封装的价签，也不应承诺能达到 Rand/0 的效果。

### 5.2 交互能力专项对比（2026-09-12）

MindReset 官方资料明确列出 Rand/0 的双按键短按/长按、摇一摇、NFC 和蜂鸣器，而不是只有屏幕。其 Display Mode 还能把上下按键事件通过网络发给外部网页。Rand/0 的体验来自“物理输入、快速增量刷新、声音确认”三者配合。

| 交互环节 | 口袋先知 Rand/0 | HINK 当前方案 |
|---|---|---|
| 设备本体输入 | 双按键、摇一摇、NFC | 没有已确认的本体输入器件 |
| 即时反馈 | 快速屏幕变化、蜂鸣器 | RGB LED 可作为即时反馈；屏幕全刷约 18 秒 |
| 手机/网页 | Wi-Fi、BLE、Display Mode | Web Bluetooth 传图和控制命令 |
| 离线玩法 | 答案书、骰子、硬币、计时等 | 固件可内置内容，但目前缺少触发入口 |
| 待机设计 | 成品方案未公开细节 | 已实测约 42 µA，修改输入电路时必须保住这一基线 |

因此，HINK 不应复制“按一下屏幕立刻变化”的体验，而应采用“输入立即由 LED 确认，屏幕在后台慢慢完成”的交互节奏。

#### 无需改硬件：优先实现

1. 把网页从传图工具扩展为答案书、硬币、骰子、随机数字和模板卡片；用户只发送一个动作命令，由价签本地生成结果，减少 BLE 数据传输。
2. 在手机网页中使用手机自身的摇动传感器，把“摇手机”转换成 BLE 命令。是否可用取决于手机浏览器对 Web Bluetooth 和动作传感器的支持。
3. 在外壳贴无源 NFC 标签或二维码，触碰/扫码直接打开该价签的控制页。NFC 标签本身不消耗价签电池；浏览器通常仍需要一次用户操作才能建立 BLE 连接。
4. 用 RGB LED 做分层反馈：收到命令短闪蓝色、开始刷新短闪绿色、失败闪红色。只进行几十毫秒事件闪烁，不恢复持续闪灯，因此对平均功耗影响很小。
5. 支持定时自动换卡片，例如每天一句、日期、纪念日倒计时。TLSR8359 可由低功耗定时器唤醒，但需要接受时钟漂移，并控制刷新频率。

#### 最小硬件改动：推荐“磁铁划过”或单按键

TLSR8359 的电源管理支持 GPIO PAD 从深睡眠/保持睡眠中唤醒。最省电的输入器件是常开干簧管或机械按键：常态开路几乎不耗电，闭合时把一个可唤醒 GPIO 拉低。

本板 RGB LED 为共阳，PC4/PC5/PC6 通过各自 1 kΩ 电阻连接 LED 阴极。理论上可以选择一个颜色通道，在 MCU 侧电阻节点增加“常开开关到 GND”，并启用内部上拉和低电平唤醒；按下时该颜色还会自然点亮，形成无需额外器件的反馈。真正实施前必须再次确认所选焊盘是电阻的 MCU 侧，并在实验机测量开路电平、唤醒可靠性和 42 µA 待机基线。

与普通按键相比，干簧管可以藏在外壳内部，通过磁铁划过触发，不需要在外壳开孔，也很符合“口袋先知”的仪式感。它是当前最适合这块价签的本体交互升级。

#### 完整体感升级：超低功耗加速度计

若要真正实现摇一摇、敲击、双击和翻转，可增加带硬件运动中断的三轴加速度计，并用其中断脚唤醒 TLSR8359。BMA400 官方给出的自唤醒模式约 0.8 µA，LIS2DW12 官方标注活动低功耗模式低于 1 µA；相对于当前 42 µA 基线，传感器本体的增量不大。

实际设计中，更容易破坏功耗的是开发板自带的稳压器、电源灯和 I²C 上拉，而不是传感器芯片。因此应使用裸芯片或无电源灯的小板，核算上拉电阻，并在焊接后重新测量整机待机电流。该方案还需要至少两根总线线、一根中断线、电源和地，工程量明显高于干簧管。

#### 推荐路线

1. 第一阶段：网页增加玩法和手机摇一摇；RGB LED 提供即时确认。
2. 第二阶段：用 PC5 或另一个确认空闲的可唤醒 GPIO 加一个干簧管，实现磁铁触发随机结果。
3. 第三阶段：只有确实需要摇一摇/敲击/翻转时，再设计 BMA400 或 LIS2DW12 小板。

其中第二阶段的“磁铁划过 → LED 立即闪一下 → 约 18 秒后显示结果”最符合现有硬件条件，也最容易保住当前低功耗成果。

## 6. 对 HINK 后续功能的启发

### 6.1 优先借鉴：网页内容生成器

无需修改价签硬件，就能在现有网页中增加：

- 答案之书。
- 每日一句或每日运势。
- 抛硬币、骰子和随机选择器。
- 日期卡片、待办卡片和状态牌。
- 黑白红模板库，红色只强调一个关键词、结果或图形。
- 图片历史和一键重新发送。

这会把当前“上传图片工具”提升为“内容生成与发送工具”，同时保持现有低功耗固件不变。

### 6.2 需要固件或硬件配合

- 增加机械按键或干簧管，切换内置页面或触发随机结果。
- 增加超低功耗加速度计，实现摇动、敲击或翻转触发。
- OTA v2 M2 已完成完整性校验、断电恢复和失败回滚；若未来用于多设备或不可信环境，再增加身份认证、固件签名和防降级。
- 本地内容库，使简单功能不依赖每次手机传图。
- 多价签管理、设备分组和独立内容配置。

### 6.3 不建议直接照搬

- 不应为了模仿 Rand/0 而引入必须经过第三方云端的图像转换链路。
- 不应让 BLE 或 Wi-Fi 长时间保持连接，破坏现有约 42 µA 待机基线。
- OTA v2 M2 已可用于当前个人项目，但仍没有身份认证和固件签名，不应向不可信环境公开升级入口；极端损坏仍需保留可重新接入 SWire 的条件。
- HINK 是 122 × 250 黑白红屏，不应直接套用 Rand/0 的 200 × 200 四灰阶版式。
