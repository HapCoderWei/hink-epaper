# 网页使用与部署

传图与 OTA 工具：<https://hapcoderwei.github.io/hink-epaper/>

固件分享页：<https://hapcoderwei.github.io/hink-epaper/firmware.html>

固件分享页是面向爱好者的统一入口，目前只展示 **HINK E-Paper Community v1.0.0**（设备内部版本 v19）。页面包含适配设备的正反面与改造效果照片、P6 实物引脚、SHA-256、TLSR 烧录器接线、首次烧录步骤、OTA 更新步骤和内置图集；开发中间镜像不会出现在该页面。维护方法见[固件发布流程](FIRMWARE_RELEASES.md)。

两个页面的用途不同：原厂价签首次接管仍需使用 TLSRPGM 烧录器和 SWire，网页不直接控制烧录器；成功刷入 HINK 固件后，传图与 OTA 工具才通过 Web Bluetooth 工作。正常 OTA 不需要保持烧录器连接。

固件页和传图工作室都提供「内置图集」，展示项目方提前适配好价签分辨率（250:122）的成品图。固件页点击卡片跳转 `index.html?art=<id>`；工作室可以在横向图集条中直接载入。两种入口都走与本地选图相同的处理和发送路径；清单由 `scripts/build-gallery.py` 生成，收录规范见 [内置图集技术方案](GALLERY.md)。

站点是纯前端，没有接口、数据库、第三方 JS 或密钥。文件选择、缩放/裁切、三色量化在浏览器 Canvas 内完成，然后通过本机蓝牙发送；不会将选择的图片上传到 GitHub。GitHub 仍会接收到加载网页的普通 HTTP 请求。

1. 用支持 Web Bluetooth 的浏览器打开 HTTPS 网址，推荐已实测的 Mac Chrome。
2. 开启蓝牙并允许操作系统/浏览器蓝牙权限；价签供电且在附近。
3. 点击连接，选择 HINK（或旧缓存 ESL）；新站点来源需要重新授权，不能继承 localhost 授权。如果系统列表为空，点击“扫描全部设备”，再选择 HINK、ESL 或可能显示为未知名称的价签。备用入口不按名称过滤，但仍只会尝试访问本项目的 GATT 服务，选错普通设备只会连接失败。
4. 点击选择、拖放或直接粘贴图片；页面默认按实体价签向右旋转 90° 后的 `250×122` 横向视图预览，也可继续点击“左转 90°”或“右转 90°”调整图片方向。页面在发送前将横向预览逆向映射回设备原生 `122×250` 像素缓冲，因此横向预览与实体价签显示方向一致，BLE 双平面格式仍保持不变。
5. 选择裁切/留白及像素处理，确认预览，再发送。“完整显示”保留整张图片并可能留白，“铺满并裁切”填满屏幕并裁掉超出部分；如果图片本身就是 250:122 比例（例如内置图集的 `500×244` 成品），两种模式的计算结果相同，切换时画面不会变化。默认“自动选择”会判断缩放后的画面更接近 Logo/文字还是照片：Logo、文字和条码自动使用清晰硬阈值，照片自动使用蛇形 Floyd–Steinberg 误差扩散。也可以手动强制选择任一模式。测试图和全白按钮只在连接成功后可用。
6. 等屏幕完整刷新，再关闭网页。页面会在连接后 1 分钟无操作时自动断开蓝牙，避免持续连接耗电；也可以随时点击顶部"断开"按钮手动断开，然后连接其他价签。

这不是远程互联网价签网关。任意手机/Safari 不保证支持此 API；以浏览器 Web Bluetooth 支持情况为准。页面需要 HTTPS 或本机安全开发来源，普通局域网 HTTP 不可靠。当前无 Service Worker，不承诺断网后重新打开网页可用。

图片先在 `750×366` 离屏画布上进行三倍采样和三色量化，再用 3×3 多数票缩回真实 `250×122` 输出，以减少 JPEG 噪声、粉红抗锯齿边缘和孤立色点。网页展示层使用平滑缩放，发送缓冲仍严格保持 `250×122`。抖动不会让三色屏产生真正灰阶，只会在固定像素中排列黑/白/红点；最终效果仍受屏幕物理点阵、观看距离和原图缩放影响。

如果更新代码后出现“文件名已变化但预览全白”，先检查 `site/index.html` 引用的 `image-processing.js` 版本参数是否同步递增。旧脚本缓存缺少新处理函数时会在清空画布后中断；本版使用 `image-processing.js?v=adaptive-3`。本地开发可清除 `localhost` 站点缓存或用隐私窗口核对，但发布时仍应更新版本参数，不能依赖用户手动清缓存。

GitHub Pages 通过 `.github/workflows/pages.yml` 发布 `site/`，不会部署固件和硬件文档目录。站点公开不等于跨互联网能直接控制蓝牙，但附近的人可能用兼容客户端写入未认证价签。

参考：[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)、[Chrome Web Bluetooth](https://developer.chrome.com/docs/capabilities/bluetooth)。

## 图集与预览优化记录（2026-09-17）

- 工作室新增内置图集条和顶部锚点，支持鼠标与键盘直接载入；选中状态、加载状态和失败提示均保留。
- 首批图集扩展为 `coca-cola-logo`、`force-logo-red`、`pepsi-logo` 三张 `500×244` RGB PNG，并由清单测试检查缺失、重复和孤儿文件。
- 预览外壳最大宽度提升到 540 px，但始终受面板的 94% 宽度约束；桌面和移动端均不会横向越界。
- Canvas 不再强制 `image-rendering: pixelated`，只柔化网页显示；设备输出分辨率、横向到原生坐标映射和 BLE 双平面数据没有改变。
- 红色门控进一步排除粉红抗锯齿边缘；三倍采样与多数票缩图均有主机回归测试。
- 当前验证范围：自动化测试和 Mac Chrome 本地预览已通过；本轮没有连接价签、发送图片、写入 Flash 或执行 OTA。

## Web v1.0 完成记录（2026-09-13）

本轮把原先的纵向表单重构为 **E-Ink Control Studio**。页面的首要任务仍是本机传图，不增加账号、接口、数据库或远程图片处理：

- 左侧为带黑/白/红识别带的电子价签数字孪生，右侧为“选择图片、调整画面、连接并发送”三步工作流。
- 图片入口支持点击、拖放和粘贴；只有图片与 BLE 连接同时就绪时才启用发送按钮。
- 连接状态常驻顶部；测试图和清屏归入设备工具；OTA 固件维护默认收起，避免与日常传图混在一起。
- M2 设备连接后分别显示当前版本、当前槽、非活动目标槽和有效/损坏恢复日志数；现有固件清单校验、稳定供电确认与两步安装门槛没有放宽。
- 预览坐标改为 `250×122`。实体面板原生坐标仍为 `122×250`；发送时使用 `landscapeX = 249 - nativeY`、`landscapeY = nativeX` 读取预览像素，对应把原生面板向右旋转 90° 后观察。
- 布局覆盖桌面和窄屏手机，键盘焦点清晰，并尊重系统的”减少动态效果”设置。
- 顶部连接状态旁新增”断开”按钮，连接后可随时手动断开并切换到其他价签，无需刷新页面。
- 连接后 1 分钟无操作自动断开蓝牙，发送图片、测试图、清屏和 OTA 操作会重置计时器。

本轮浏览器验收包括：默认横向占位图、带明确左右方向的横向图片、文件选择、自动三色量化、左右旋转、OTA 展开/收起、手机断点和控制台错误检查。主机测试新增 `tests/web_ui_test.js`，检查关键控件、OTA 默认安全状态、脚本语法及横向四角坐标映射；完整 `tests/run.sh` 通过。

本轮没有连接价签、写入 Flash 或触发 OTA。横向坐标关系已经由浏览器画面和主机映射测试确认，但实体价签方向仍应使用带左右箭头的测试图片完成一次 BLE 传图验收后，再标记为真机确认。

## OTA v2 固件维护区

网页 v1.0 将折叠的“固件维护”与日常传图工作流分开，并把日常画面工作区改为实体价签右转 90° 后的横向视图。它首先向 `0x221f/0x331f` 发送 OTA v2 `INFO` 握手，只有运行 M0/M1/M2 开发固件的测试价签才会启用文件选择。已发布 B1、`v0.1.1-name` 以及继承的旧 ATC OTA 服务不会通过握手。客户端接受 20 字节 M0、24 字节 M1-B、28 字节 M1-C 和 32 字节 M2 状态；界面会分别显示当前版本、当前槽、非活动目标槽及有效/损坏恢复日志数。

M0 只执行暂存区擦除、顺序小包上传、逐包 Flash 读回和 CRC32 校验。M1 改为写 SDK 选择的非活动启动槽，上传时把候选镜像偏移 8 保持为 `0xFF`，并在结束时复读验证 HINK 清单、Telink 头部/长度及两层 CRC。仅当设备声明安装能力、候选清单有效且状态为 `VERIFIED` 时，页面才显示安装区；用户还必须勾选稳定外部 3.3 V/SWire 确认，并分别点击“授权安装”和“切换槽位并重启”。上传达到 100% 本身仍不代表设备已经升级。完整阶段和真机验收条件见 [OTA v2 里程碑](MILESTONE_OTA_V2.md)。
