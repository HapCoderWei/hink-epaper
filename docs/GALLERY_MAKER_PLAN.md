# HINK 图集制作器实施方案

方案日期：2026-09-17  
实施日期：2026-09-18  
状态：**已实施并完成自动化与浏览器验收**

## 1. 目标

新增一个公开可访问的网页工具，把访客上传的普通图片处理成适合 HINK 2.13 英寸黑白红电子价签的成品图。

页面只承担一个核心任务：

> 上传图片 → 调整构图 → 查看真实三色预览 → 导出符合图集规范的 PNG。

所有访客都可以在浏览器中处理和下载图片；项目维护者还可以主动选择本地仓库的 `site/assets/gallery/` 目录，把成品和图集元数据直接保存到本地项目。

## 2. 已确认的产品决策

| 页面路径 | `site/gallery-maker.html` |

| 输出格式 | `500×244` RGB PNG、白底、无透明通道、黑白红三色、≤ 300 KiB |

## 3. 能力边界

### 3.1 公开页面能做什么

- 点击、拖放或粘贴 JPG、JPEG、PNG、WebP 等浏览器可读取的图片。
- 调整缩放、位置、旋转和铺满/完整显示。
- 使用自动、清晰边缘或照片抖动三种处理方式。
- 查看 `250×122` 价签真实像素预览。
- 导出符合项目规范的 `500×244` RGB PNG。
- 显示输出尺寸、文件大小和黑/白/红像素比例。

### 3.2 公开页面不能做什么

- 不能直接修改 GitHub 上的仓库。
- 不能自动提交、推送或发布到 GitHub Pages。
- 不能让普通访客未经审核把图片加入项目公共图集。

### 3.3 维护者本地保存

在支持 File System Access API 的桌面 Chromium 浏览器中，页面显示“选择图集目录”按钮。维护者主动选择本地仓库中的：

```text
site/assets/gallery/
```

页面获得本次授权后，可以在该目录内写入成品 PNG、图集目录数据和生成后的 `manifest.json`。

页面必须验证选中的目录中已有 `manifest.json` 或约定的图集目录文件，避免误选普通文件夹。目录权限只能由用户点击按钮后授予；不支持该能力的浏览器保留“下载 PNG”功能。

参考：

- <https://developer.chrome.com/docs/capabilities/web-apis/file-system-access>
- <https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker>

## 4. 页面信息架构

页面采用真实工作流，而不是通用后台表单：

1. **选择图片**
2. **调整画面**
3. **确认电子纸效果**
4. **下载或保存**

## 5. 视觉方向

页面延续现有 HINK Control Studio，而不是创建一套新的通用上传工具风格。

### 5.1 色彩 Token

| 用途 | 颜色 |
|---|---|
| 墨黑 / 主体 | `#171B1D` |
| 电子纸黑 | `#111111` |
| 纸白 | `#FFFFFF` |
| 矿物灰背景 | `#EDF1F0` |
| 电子纸红 | `#CF2028` |
| 状态青绿 | `#167C78` |

### 5.2 字体角色

- 标题：`Avenir Next Condensed` / `PingFang SC`，保持现有工作室的窄体工业感。
- 正文和控件：`Avenir Next` / `PingFang SC`。
- 尺寸、文件名、像素统计：`SFMono-Regular` / `Menlo`。

### 5.3 视觉签名

页面唯一需要突出的设计元素是“真实电子纸预览”：以价签屏幕边框包住 `250×122` 三色像素结果，并在旁边显示黑、白、红像素比例。其余界面保持克制，不加入无用途的装饰动画。

## 6. 图片处理管线

尽量复用 `site/image-processing.js`，避免图集制作器和传图工作室得到不同结果。

### 6.1 输入处理

1. 浏览器解码用户图片。
2. 透明区域统一铺白底。
3. 按用户设置执行旋转、缩放和位置调整。
4. 支持：
   - 完整显示（contain）
   - 铺满并裁切（cover）
   - 缩放滑杆
   - 水平和垂直位置调整
   - 左转 / 右转 90°

### 6.2 三色量化

复用现有色板和处理逻辑：

- 白：`255, 255, 255`
- 黑：`17, 17, 17`
- 红：`207, 32, 40`
- 自动模式：自动判断文字 / Logo 或照片。
- 清晰边缘：硬阈值，适合 Logo、文字和条码。
- 照片模式：蛇形 Floyd–Steinberg 抖动。
- 继续使用高分辨率采样和多数票缩小，减少 JPEG 噪点和红色边缘杂点。

### 6.3 输出策略

1. 先得到准确的 `250×122` 三色设备预览。
2. 使用最近邻方式将每个设备像素扩展为 `2×2` 像素块。
3. 输出 `500×244` RGB PNG。
4. 不保留 Alpha 通道，不引入额外颜色。

这种输出可以保证图集成品与价签真实像素之间保持一一对应，同时满足现有图集推荐尺寸。

## 7. 交互细节

### 7.1 上传

- 支持点击、拖放和剪贴板粘贴。
- 未选择图片时，预览区显示现有黑白红占位画面。
- 文件无法解码时提示“无法读取这张图片，请改用 PNG、JPG 或 WebP”。

### 7.2 调整

- 鼠标或触摸拖动画面调整位置。
- 缩放滑杆提供有限范围，避免画面被无限放大。
- 旋转和处理模式变化后立即更新真实预览。
- 尊重 `prefers-reduced-motion`，不添加持续动画。

### 7.3 元数据

维护者保存到图集时填写：

- 文件名 slug：只允许 `[a-z0-9-]`
- 标题：公开展示名称
- 分类：短文本标签

普通访客下载时只要求文件名；标题和分类为可选。

### 7.4 保存状态

保存按钮只在以下条件全部满足时启用：

- 已成功载入图片。
- 输出尺寸为 `500×244`。
- 输出为 RGB PNG 且无透明通道。
- 文件大小不超过 `300 KiB`。
- slug 合法。
- 图集目录已经授权。
- 图集未超过 24 张。
- 目标文件不存在。

默认禁止覆盖已有文件。重名时提示修改 slug，不在第一版加入覆盖确认流程。

## 8. 图集数据结构调整

### 8.1 当前问题

当前图片标题和分类硬编码在 `scripts/build-gallery.py` 的 `TITLE_MAP` 中。公开网页不应修改 Python 源码，因此需要把可编辑数据移出脚本。

### 8.2 建议结构

新增：

```text
site/assets/gallery/catalog.json
```

格式：

```json
{
  "version": 1,
  "images": {
    "force-logo-red": {
      "title": "Force Logo · 红色版",
      "category": "标语"
    }
  }
}
```

职责划分：

- `catalog.json`：标题和分类的可编辑数据源。
- 图片文件：实际 PNG/JPG 资源。
- `manifest.json`：供公开网页读取的排序后发布清单。
- `scripts/build-gallery.py`：读取目录与 `catalog.json`，校验后生成或检查 `manifest.json`。

图集制作器本地保存时：

1. 写入 `<slug>.png`。
2. 更新 `catalog.json`。
3. 按与 Python 脚本相同的排序和字段规则更新 `manifest.json`。

后续运行 `python3 scripts/build-gallery.py --check` 时，必须能验证浏览器生成的结果与脚本预期完全一致。

## 13. 人工验收

1. Mac Chrome 上传一张普通照片，使用照片模式导出 PNG。
2. 上传一张 Logo，自动模式应选择清晰边缘。
3. 拖动、缩放、旋转后，编辑画面和真实预览一致。
4. 下载文件确认为 `500×244` RGB PNG、无透明通道、≤ 300 KiB。
5. 选择本地 `site/assets/gallery/`，保存一张测试图片。
6. 新图片、`catalog.json` 和 `manifest.json` 同步更新。
7. 新图片立即能在固件页和控制工作室图集条中加载。
8. 重名、错误目录、非法 slug、超限图片分别显示明确提示。
9. 在不支持目录写入的浏览器中，页面仍能完成处理和下载。
10. 桌面 1440 px 与手机 390 px 无横向溢出。
11. `bash tests/run.sh` 全部通过。

## 14. 安全与隐私

- 图片处理不离开浏览器，不发送到项目服务器或第三方服务。
- 目录访问必须由用户点击触发并主动选择目录。
- 页面不保存 GitHub 凭据，也不调用 GitHub 写入 API。
- 写入前验证目标目录和文件名，禁止路径分隔符与 `..`。
- 第一版不允许覆盖、删除或移动已有图片。
- 公开访客只能下载本地文件，不能发布到项目公共图集。

## 15. 非目标

第一版明确不做：

- AI 图片生成。
- 在线账户、用户图库或云端存储。
- GitHub 登录、自动提交、自动开 Pull Request。
- 多图批量处理。
- 图层、画笔、文字排版等完整图片编辑器能力。
- 已发布图集的删除、排序和批量管理。
- 自动判断版权或审核访客图片内容。

## 16. 已确认的 Review 决策

1. 控制工作室和固件页都保留公开导航入口。
2. 所有人都可在浏览器本地处理和下载；只有维护者主动授权本地目录后才能写入图集。
3. 使用 `catalog.json` 取代 Python `TITLE_MAP`。
4. 先生成 `250×122` 三色结果，再以最近邻放大为 `500×244`。
5. 第一版保留拖动、缩放、旋转、contain 和 cover。
6. 禁止覆盖已有图片；保存前验证两个 JSON，失败时尽力恢复原文件并移除本次新建 PNG。
