FIRST FLASH · WIRING

TLSR 烧录器怎么接价签

烧录接口是单线 SWire。程序信号只有一根，但供电方式必须正确：SWM 接 SWS、所有设备共地，并且整板只能有一个 3.0～3.3 V 电源。

接线前先取下两颗电池禁止 5 V；禁止电池与外部 3.3 V 同时供电；不确认引脚时先用万用表通断档核对。

PATH A · SWIRE

首次烧录步骤

适用于原厂固件、B1 / v0.1.x、版本未知或 OTA v2 握手失败的价签。第一次接管设备必须先保存原厂 Flash。

  1. 确认设备与文件

    核对屏幕 FPC、MCU 和 Board ID；下载社区版固件，并确认 SHA-256 与页面一致。

  2. 断电后接线

    取下电池，按上方推荐图连接 SWM、GND 和独立 3.3 V。接线完成后再给价签供电。

  3. 先读芯片信息

    TLSRPGM 必须能稳定识别目标 MCU 与 Flash。出现激活超时、Flash ID 为 0 或读出全 0 时停止，不继续写入。

  4. 备份完整原厂 Flash

    从 0x000000 读取 0x80000 字节并保存两份；确认两次备份 SHA-256 相同且内容不是全 0。

  5. 从 0x000000 写入固件

    使用带扇区擦除的写入操作，只让工具擦除固件覆盖到的扇区；不要执行整片擦除。

  6. 写后读回 0xEF88 字节

    读回长度必须与固件 61,320 字节一致，并逐字节比较；读回文件 SHA-256 应为页面公布值。

  7. 恢复供电并验证功能

    停止外部供电、拆下烧录线，再装回电池。确认广播名称为 HINK_XXXXXX，连接网页并发送测试图，观察黑、白、红完整刷新。

展开 TLSRPGM 命令示例

以下参数来自本项目已验证工具链。把串口和脚本路径替换成自己的实际位置；串口每次连接都可能变化。

python3 TlsrPgm.py -w -p /dev/cu.usbmodemXXXX -b 1500000 -t 50 -a 5000 i python3 TlsrPgm.py -w -p /dev/cu.usbmodemXXXX -b 1500000 -t 50 -a 5000 rf 0x000000 0x80000 HINK_original_backup.bin python3 TlsrPgm.py -w -p /dev/cu.usbmodemXXXX -b 1500000 -t 50 -a 5000 we 0x000000 HINK_E0213A162_Community_v1.0.0.bin python3 TlsrPgm.py -w -p /dev/cu.usbmodemXXXX -b 1500000 -t 50 -a 5000 -g rf 0x000000 0xEF88 HINK_v1.0.0_readback.bin shasum -a 256 HINK_E0213A162_Community_v1.0.0.bin HINK_v1.0.0_readback.bin

不要加入 -c / CPU Stall；本项目实测它会导致 TLSR8359 Flash 识别与读取异常。

PATH B · OTA v2 M2

后续 OTA 更新步骤

只有已经运行 OTA v2 M2、网页能读出当前版本和槽位的价签才能走这条路径。旧 ATC OTA 页面始终禁止使用。

  1. 准备稳定供电

    确认电池接触可靠或使用稳定 3.0～3.3 V；保留原始备份和可重新接入的 SWire 焊盘。

  2. 下载并校验固件

    确认文件名、板型、长度和 SHA-256；不要使用诊断版、故障注入版或来源不明的转载文件。

  3. 连接价签并检查状态

    用 Mac Chrome 打开控制工具，在“固件维护”中核对当前版本、活动槽、目标槽和恢复日志。

  4. 上传并由设备完整校验

    选择固件并点击“上传并校验”。进度 100% 仍未安装；必须等页面明确显示候选固件已经板端校验通过。

  5. 完成两步安装

    勾选稳定供电确认，依次点击“准备安装”和“安装并重启”，不要刷新或关闭页面抢跑下一步。

  6. 重连并验收

    重新连接，确认版本已经变化、槽位符合预期且恢复日志无损坏，再发送测试图确认三色刷新。
